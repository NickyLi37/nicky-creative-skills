# 提示词优化版（苏州《人家尽枕河》）

> v2（2026-11-03）：片名定为《人家尽枕河》，时长 165 s，成片 4K，字幕围着「人家 + 水」改写，数据署名按各数据集的许可写全。

## A. 原提示词的问题与改法

| # | 原提示词 | 问题 | 优化版的做法 |
|---|---|---|---|
| 1 | 推荐 Open3D / PyVista | 这两个是科研可视化工具，做不出原片的移轴景深、AO、辉光，也不好排中文 HUD | Python 只做数据，渲染改用 Three.js + 自定义着色器，用 Playwright 逐帧截图，HUD 用 HTML/CSS 叠层 |
| 2 | 「149 秒、约 3573 帧」 | 没写帧率，数字也对不上（原片实际是 24 fps、148.75 s） | 写明 24 fps、3960 帧（165 s），**帧号是唯一的时间源** |
| 3 | 「建筑根据年龄属性逐步生长」，覆盖三千年 | CMAB 的年代字段只覆盖 1985–2018，古代段根本没有数据，按这个写只能硬编 | 古代段用专题图层（城墙、水道、桥、门位、园林），标「示意」；建筑年代只用在 1985 年以后的两翼生长 |
| 4 | 没有区分事实和示意 | 原片自己标了「示意」，提示词里却没有这条要求 | 加一条硬规则：每条字幕都要对应来源；推测的内容一律标示意；有争议的说法不许写得更肯定 |
| 5 | 没有中间检查点，要求「直接给完整代码」 | 149 秒的片子一次写完，改起来非常痛苦 | 分 5 个阶段，每个阶段停下来确认：架构、数据、样张、预览、成片 |
| 6 | 「左右双语字幕」 | 和原片不符：原片字幕在底部，中上英下，章节块在左边 | HUD 按原片的真实布局写到像素级 |
| 7 | 「镜头从高空俯视缓推」 | 太含糊，模型只能自由发挥 | 每段写明机位、景别和运镜方向，用 timeline.json 驱动 |
| 8 | 字段名靠假设 | 「含屋顶轮廓、高度、估算年龄」，字段名都是猜的 | 先读 README 和元数据，打印字段与取值分布，再写清洗逻辑 |
| 9 | 没有验收标准 | 做完了也不知道算不算合格 | 附一份 QA 清单：确定性、字幕安全区、事实一致性、闪烁等 |
| 10 | 没提音频 | — | 写明纯配乐、无旁白，交付 SRT |

## B. 优化后的提示词（可直接使用）

```text
你是资深的程序化动画导演兼图形工程师（Three.js / GLSL / Python 地理数据处理）。
任务：全部用代码渲染一部城市白模纪录短片《人家尽枕河》（苏州）。
片名出自唐 · 杜荀鹤《送人游吴》「君到姑苏见，人家尽枕河」，全片文本都围着「人家 + 水」写。
工作分 5 个阶段，每个阶段结束都停下来，等我确认后再继续。

━━━━━━━━ 一、成片规格 ━━━━━━━━
- 成片 3840×2160（4K），24 fps，165.0 s，共 3960 帧。帧号 f 是唯一的时间源。
- 版式按 1920×1080 设计，渲染时 devicePixelRatio = 2 直接出 4K（4× MSAA）；预览用 960×540。
- 交付 PNG 序列、4K H.264（高码率）与 HEVC 母版，以及中英 SRT。
- 纯配乐，无旁白，音乐另给。字幕和 HUD 直接渲染进画面。

━━━━━━━━ 二、数据（统一投影：以古城中心 120.6230E / 31.3110N 为原点的横轴墨卡托，单位米）━━━━━━━━
1. 建筑：CMAB 数据集（Zhang, Zhao & Long, 2024，figshare，doi:10.6084/m9.figshare.27992417，CC BY 4.0），用 jiangsu.zip 里的 processed_suzhou_20210114_all.shp。
   - 先读 README 和 metadata，打印字段名、类型和取值分布。不要猜字段名。
     实测：EPSG:3857，字段 Height / Function / Age / Quality / Structure / Style；Age 为 1984（≤1985）到 2018 的年份。
   - CMAB 的高度是模型估算，超高层被压低（全市最高只有约 104 m），所以园区地标必须手动覆盖。
   - 裁剪范围：西到狮山、何山，东到金鸡湖东岸，北过虎丘，南到宝带桥，约 22×14 km（边界在阶段 2 定稿）。
   - 保留字段：轮廓、height(m)、建成年代（1985–2018 的年份 / ≤1985 / 2018 年以后）、功能。
   - 清洗规则：
     - 面积小于 15 m² 的剔除；
     - height 缺失的，用同一街坊的中位数补，并记录补值比例；
     - 轮廓按 Douglas-Peucker 0.5 m 简化。
2. OpenStreetMap（用 Overpass 按同一范围拉取）：
   - 水系：区分护城河、运河、古城内河道、湖泊；
   - 主干路网；
   - 桥：bridge=yes；
   - 城墙遗存：historic=citywalls；
   - 九座世遗园林（按名称匹配）；
   - 塔：北寺塔、虎丘塔、瑞光塔、双塔；
   - 城门：盘、阊、胥、娄、齐、平、相、葑。
3. 平江图（1229，南宋石刻）：
   - 根据拓片图像描线：城墙、城门、主要河道、主要街道、桥位、子城，存成 SVG；
   - 用 15 个左右控制点做最小二乘仿射配准，输出残差报告（实测 TPS 会把直线扭弯，不用）；
   - 片中凡是用到它的地方，一律标注「示意重绘」。
4. 地标高度手动覆盖：
   - 苏州国际金融中心 450 m；
   - 东方之门 301.8 m；
   - 北寺塔 76 m；
   - 虎丘塔约 48 m，塔顶向东北偏离 2.34 m。
5. 派生图层：
   - 被填河道：把平江图河道缓冲 15 m，减去现状水系，标「示意」；
   - 分区：古城（护城河内）/ 西翼 / 东翼。
6. 输出：
   - 按 1 km² 分块的二进制几何。每个顶点带 position、normal，以及属性
     ageYear、height、zoneId、flags（bridge / garden / wall / lostCanal）；
   - manifest.json；
   - data_report.md，内容包括：楼栋总数；古城、西翼、东翼的高度分位数；
     古城内最高建筑及其高度；配准残差。（已核实：古城南部有一座 151 m 电视塔，所以不能说「古城天际线属于北寺塔」）

━━━━━━━━ 三、叙事时间轴（用 timeline.json 驱动）━━━━━━━━
每个章节包含这些字段：
id、帧区间、章节名（中/英）、大字、时代状态、镜头关键帧、显示的图层、标注、字幕（中/英）。

━━━━━━━━ 六、工程架构 ━━━━━━━━
prep/   fetch_osm.py · cmab_clip.py · pingjiang_georef.py · build_tiles.py · report.py
render/ index.html · app.ts · timeline.ts · camera.ts · materials/building.glsl · water.glsl · hud.ts
        capture.mjs · encode.sh

关键接口：
- initScene(manifest)：加载分块，每块合并成一个 Mesh，共享一个 ShaderMaterial。
- stateAt(f) → { camera, uniforms, hud }：纯函数，只依赖 f 和 timeline.json。
- renderFrame(f)：调用 stateAt，渲染，再更新 HUD DOM。
  不允许用 requestAnimationFrame、Date.now 或未设种子的随机数。
- capture.mjs：
  - 用 Playwright 起 N 个 worker 分帧段渲染；
  - 已存在的帧直接跳过，可以断点续跑；
  - 支持 --from / --to / --scale / --stills 参数。

性能要求：
- 每帧不在 CPU 上改几何。显隐、生长、着色全部由 uniform 驱动（uYearCutoff、uEraA/B、uWipe 等）。
- 远处分块用 LOD；单帧显存控制在 4 GB 以内。

━━━━━━━━ 七、事实与标注硬规则 ━━━━━━━━
- 每条事实性字幕和标注，都要在 sources.json 里对应一个来源 URL。
- 复原线条、推测的范围和位置，一律标「示意」。
- 有争议的说法，严格照方案措辞，不得写得更肯定。例如城址问题，要带小字注「学界尚有讨论」。
- 禁用以下说法：平江图桥数；古城限高 24 m；「唯一以古城概念申遗」；虎丘塔倾角度数；1860 年火是谁放的；「古城天际线属于北寺塔」。
```
