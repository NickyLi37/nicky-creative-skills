# 《人家尽枕河》制作总结

苏州白模城市短片，4K，4 分 18 秒。形式参考 @EianLu 的成都城市短片（x.com/EianLu/status/2111662397278847478）。画面全部用代码渲染，旁白和配乐由 Claude 通过 Sumi Studio 的 MCP 生成。片名取自杜荀鹤《送人游吴》：「君到姑苏见，人家尽枕河。」

制作时间 2026 年 11 月 2 日至 3 日，前后改了五轮。

## 二、跟帖素材：Claude 怎么调 Sumi MCP

Claude 在 Claude Code 里直接调用 Sumi Studio 的 MCP 工具，用的是用户本人账号的积分，每次花钱前先报价。一次生成的调用顺序：

1. `get_model` 查模型能接受的参数，比如 `speech-2.8-hd` 支持的音色、情绪、语速、音高和读音词典。
2. `create_generation_task` 提交任务，带一个固定的 `idempotencyKey`，网络出错重试时不会重复扣费。
3. `wait_task` 等任务完成，`get_asset_download_url` 拿到原始 wav，下载到项目的 `vo/` 或 `music/` 目录。
4. 下载后在本地测时长、音高和响度，用 Whisper 逐句识别核对字错，不合格就换参数重来。

旁白的参数：

```json
{
  "modelKey": "speech-2.8-hd",
  "taskType": "text_to_audio",
  "input": {
    "prompt": "一二二九年，平江府把整座城刻上了石碑。",
    "voice": "Chinese (Mandarin)_Lyrical_Voice",
    "emotion": "calm", "speed": 1,
    "audioFormat": "wav", "sampleRate": "44100", "languageBoost": "Chinese",
    "pronunciationDict": ["阊门/(chang1)(men2)", "胥门/(xu1)(men2)", "相门/(xiang1)(men2)", "枕河/(zhen3)(he2)"]
  }
}
```

全片旁白一次合成一整段，再按句切开，这样语气是连贯的。后来个别句子要改，就单独重配，用同样的音色和参数。地名多音字用 `pronunciationDict` 标注，比如「相门」不加标注会被读成「巷门」。

配乐的参数：`chirp-v6`，`customMode` 和 `forceInstrumental` 打开，输出 wav，一次任务出两首。提示词写清楚乐器（钢琴、弦乐、琵琶、三弦，点一点笛子）和情绪走向（比如后段一路推高）。每一首拿到后先画响度和明暗曲线，再决定用哪首、从片中第几秒起。

## 三、整体流程

1. **拆参考片**：把 @EianLu 的成都片按帧拆开（148.75 秒，24 fps，纯配乐，叙事全靠字幕），记下镜头节奏、字幕版式、白模材质和信息卡的样式。
2. **定题和写稿**：选「人家」和「水」作为全片的线，从六千年前的稻田讲到今天。每一句旁白都查过出处，查不实的不写。比如古城里有一座 151 米的电视塔，所以没有写「古城的天际线属于宋塔」。
3. **处理数据**（`prep/`）：
   - 把 CMAB 建筑裁到片子范围，拉伸成白模，打包成二进制。
   - 从 OSM 取道路、水系、城墙和桥。
   - CMAB 的楼高被压缩过，最高只到约 104 米，所以园区的超高层用 OSM 标注的楼高覆盖，比如苏州国际金融中心 450 米。
   - 平江图描线后用控制点做仿射配准，叠到今天的水系上。碑上 169 段河道里，有 44 段和今天的水道相距不到 70 米。
4. **渲染管线**（`render/`）：Three.js 在无头 Chrome 里渲染，每一帧完全由帧号决定，所以可以多进程并行，也可以只重渲改过的几段。景深、泛光、调色和颗粒在后期通道里做；字幕、年份游标和信息卡是叠在画面上的网页层。
5. **时间轴**（`render/src/timeline.js`）：画面按 3,960 个「故事帧」编排，镜头、图层和年份都是故事帧上的关键帧。旁白按原速摆进去以后，用一条平滑的映射曲线把成片帧对应回故事帧，画面在停顿处慢下来。
6. **旁白和配乐**：在 Sumi 生成，做法见上一节。
7. **对音乐**：句与句之间的停顿可以单独加长，用来把配乐的段落对到画面上。比如最终版里，战火两句落在全曲最暗的一段，配乐全编制进入时正好接「一九八二年」，全曲最亮的地方对上 450 米的金融中心。
8. **混音**（`vo/mix_v2.py`）：配乐整体压低 4 dB；有人声时只压 250 Hz 到 5 kHz 这一段频带，最多压 4.5 dB，压多少取决于那一刻配乐在这个频段有多响。低频和高频不动，所以配乐的起伏在人声底下还在。
9. **质检**：逐句语音识别算字错率，逐帧找画面跳变，核对每句旁白说到的年份和画面上的年份游标，看音高和响度，最后看一张联系表。
10. **出片**：先出 540p 预览（全片约 11 分钟）给用户看，确认后渲 4K，编码出 4K 成片和 30 MB 以内的 1080p 手机版，另交中英 SRT。

## 四、思考过程：几个关键决定

**画面为什么全用代码渲染。** 每一帧只取决于帧号，改一句旁白、挪一个镜头，只需要重渲受影响的那几段。540p 全片预览约 11 分钟就能渲完，所以每轮修改都能先看整片再出 4K。

**画面按故事帧编排，旁白定成片长度。** 第一版为了塞进 165 秒，旁白加速了 1.2 倍，用户听着赶。第二轮起旁白一律原速，片长跟着旁白走，画面靠映射曲线拉伸。这样改旁白不用重新编排画面，代价是旁白里提到的年份要和画面上的年份游标逐句对一遍。第二轮就出过「四年后」说出口时游标还停在 1990 的问题，后来改成游标在这句话里从 1990 走到 1994。

**配乐是一整首曲子，不剪。** 想让某个音乐段落对上某句话，就调整句间停顿，或者换一首；曲子本身不剪开重排。这一轮用户要求配乐从第一帧就起，原来那首对不上，就换了同一批生成的另一首，三处停顿加长后正好对齐。

**事实只写查得到的。** 查不到的说法用更保守的措辞：平江图的河道和今天对得上的比例是 44/169，所以旁白说「不少」，没有说「大多」。

**敏感的近现代史不进片子。** 第四轮删掉了 1958 到 1972 年拆城墙、填河道的一章，换成古城保护和城墙修缮：1982 年首批国家历史文化名城，1986 年总体规划写明「全面保护古城风貌」，平江路、山塘街整修，盘门、胥门、阊门、相门一带修缮。

| 轮次 | 用户意见 | 改法 |
|---|---|---|
| 第一轮 | 虎丘到平江图那一下切得生硬；希望先看到真碑；加旁白 | 先出拓片照片，再溶解成线条、白模和卫星图；加了跟字幕走的男声旁白 |
| 第二轮 | 旁白太赶；楼是一批一批冒出来的；配乐压得太狠 | 旁白改原速，片子从 165 秒拉到 263.8 秒；每栋楼单独按年代长出来；混音改成只压人声频带 |
| 第三轮 | 说到修园子时镜头没给到拙政园；结尾加竖排书法「苏州」；念诗要有诗韵；配乐太平 | 镜头推到拙政园；片尾右侧加马善政毛笔字体的竖排「苏州」，逐字显现；重新生成四首配乐，挑后段起情绪的一首 |
| 第四轮 | 拆城墙、填河那段太敏感，不讲；多讲古城保护；战火处配乐要沉；念诗低一点 | 删去一章，改写成保护和修缮；换一首中段有暗段的配乐，把战火对进去；念诗压低音高重配 |
| 第五轮 | 配乐要从第一帧就起；念诗低得吓人，按正常旁白读 | 换同批另一首配乐，从第 0 秒起；念诗改用整段旁白里原来那一句；顺手修了片尾淡出时露出的地图黑边 |

## 六、经验

1. **单独一句不要做特别处理。** 念诗这一句前后改了三次：放慢、读得起伏大一些，显得太高昂；压低音高、加悲伤情绪，又显得吓人。最后用和全片旁白同一次录的那一句，用户才满意。
2. **配乐要从第一帧就在。** 为了让段落对齐，把配乐推迟 10 秒进场，用户一听就发现了。对齐应该在曲子里找段落，或者换曲子。
3. **先画曲线再选配乐。** 每首曲子都按秒算响度和频谱重心（越低越暗），标出暗段、全编制进入、最亮处和尾声，再拿去对旁白。比反复试听可靠。
4. **年份、数字和画面要逐句核对。** 改完时间轴以后，跑一遍脚本，把每句旁白说到的年份和游标上的年份对一遍。
5. **修一处，整片复查一次。** 每轮改完都重跑语音识别、跳帧扫描和联系表。第五轮复查时发现片尾黑边，这个问题第四轮就有，之前没看出来。
6. **CMAB 的楼高被压缩过。** 超高层要用 OSM 的楼高覆盖，否则 450 米的楼只有 100 米出头。
7. **Whisper 会把「枕河」听成「整合」。** 这是识别的问题，旁白本身读对了。判断读音时要结合音高和人耳，不能只看识别结果。
8. **AAC 编码会让峰值变高。** 96k 的 AAC 让真峰值冒到 +0.3 dBTP，限幅器从 0.93 降到 0.9，手机版用 0.87。
